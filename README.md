# Маркетплейс по доменам

Страница для защиты ДЗ «Архитектурное проектирование маркетплейса»: [marketplace.maserov.com](https://marketplace.maserov.com). Само решение — диаграмма, описание и сервис — лежит в [masesmirnov/marketplace-architecture](https://github.com/masesmirnov/marketplace-architecture).

На странице:
- **живая C4-диаграмма контейнеров:** по клику на контейнер видно, каким доменом он занят, какими данными владеет, кого вызывает и какие события публикует;
- **оформление заказа по шагам:** сага в четырёх сценариях — оплата прошла, отказ банка, таймаут, возврат;
- **три варианта разбиения на одной схеме** с плюсами и минусами;
- **живой `GET /health` настоящего `catalog-service`;**
- **общая доска:** все, кто открыл ссылку, рисуют вместе и видят курсоры друг друга. Шаги саги и выбранный вариант тоже общие.

Устанавливается из `masesmirnov/infra` скриптом `scripts/deploy_marketplace.py` по файлам, закреплённым хешами в `locks/marketplace.json`.

## Запуск

Нужен Node.js 20+, зависимостей нет.

```sh
node server.js
```

Сервер слушает `127.0.0.1:8098` (`PORT` и `HOST` меняют адрес). Доска работает через SSE `/api/stream` и `POST /api/ops`; рисунки живут в памяти и пропадают после суток без посетителей.

Живому health-check нужен сервис каталога и его адрес в `CATALOG_URL`:

```sh
cd public/catalog
pip install fastapi==0.141.1 uvicorn==0.54.0
uvicorn main:app --host 127.0.0.1 --port 8099
cd ../.. && CATALOG_URL=http://127.0.0.1:8099/health node server.js
```

Страница спрашивает `GET /api/health`, сервер ходит в `catalog-service` с таймаутом 1,5 секунды и отдаёт код ответа, тело и задержку.

## Данные

`public/catalog/main.py` — снимок `services/catalog/main.py` из репозитория решения: его строки показывает страница, его же запускает служба на сервере. Схема на странице нарисована по тем же координатам, что `docs/c4-container.svg` в решении, а тексты описаний, данных и связей взяты из его README (`public/model.js`).
